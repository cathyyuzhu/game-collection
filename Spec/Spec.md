## F001 · 首页 - 排行榜展示
### 描述
首页核心模块，展示 iOS + Android 双平台的综合热度排行榜和分类榜单，是用户的第一印象页和 SEO 流量落地页之一。

### 触发场景 / 前置条件
- 用户访问根路径 `/`（自动根据浏览器语言跳转到 `/zh-CN`、`/zh-TW` 或 `/en`）
- 每日凌晨定时任务重新计算榜单权重

### 用户故事
> 作为手游玩家，我希望进入首页就能看到当前最火的手游排名，以便决定下一款玩什么。
> 作为搜索「手游排行榜 2026」来到网站的用户，我希望看到可信的、有数据支撑的排名，而不是广告软文。

### 交互流程
1. 用户进入首页，首屏展示「🔥 综合热度榜 Top 20」（卡片式列表，显示排名、游戏图标、名称、分类、综合评分、双平台热度条）
2. 点击综合榜卡片 → 跳转至对应游戏详情页
3. 首屏下方展示分类 Tab：角色扮演 / 策略 / 休闲 / 射击 / 卡牌 / 模拟 / 动作
4. 点击分类 Tab → 切换显示该分类下的 Top 10 榜单
5. 页面底部展示「📖 最新更新攻略」区（8 篇最新发布的攻略卡片）
6. 支持切换语言后，榜单保留当前 Tab，内容自动切换到对应语言

### 输入
| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| locale | enum | 是 | 当前语言 | zh-CN / zh-TW / en |
| category | string | 否 | 分类筛选 | 空=综合榜 |
| page | int | 否 | 榜单翻页（V1 只展示前 20，无需翻页） | 默认 1 |

### 输出
| 字段 | 类型 | 说明 |
|------|------|------|
| globalRankings | GameCard[] | 综合榜 Top 20 |
| categoryRankings | Record\<category, GameCard[]\> | 各分类 Top 10（SSR 预取前 3 个分类，其余 Tab 懒加载） |
| latestGuides | GuideCard[] | 最新攻略 8 篇 |

### 异常 / 边界情况
| 场景 | 期望行为 |
|------|----------|
| 数据库暂无排行榜数据（首次上线） | 显示骨架屏 + 「榜单正在生成中...」提示，定时 5 秒刷新一次 |
| 某分类游戏不足 10 款 | 按实际数量展示，不补空 |
| 语言切换后，某游戏暂无该语言的翻译 | 游戏名称回退到英文，显示「翻译中」徽章 |

### 验收标准（AC）
- [ ] AC1：给定首页访问，首屏加载 ≤ 1.5s（LCP），展示完整综合榜 Top 20
- [ ] AC2：给定分类 Tab 点击，切换时间 ≤ 200ms，列表内容正确变更
- [ ] AC3：给定游戏卡片点击，正确跳转至该游戏的 `/{locale}/games/{slug}` 页面
- [ ] AC4：给定三语切换，URL 正确变更为对应 locale 前缀，榜单数据正确切换语言

## F002 · 游戏发现页（列表 + 分类筛选 + 搜索）
### 描述
`/{locale}/games` 页面，支持按平台、分类、首字母、关键字筛选和搜索游戏列表。

### 触发场景 / 前置条件
- 用户点击顶部导航栏「全部游戏」
- 站内搜索关键字为空或搜索结果页的「查看全部」链接

### 用户故事
> 作为想找某类型游戏的玩家，我希望能按分类和平台筛选，以便快速找到我感兴趣的游戏。

### 交互流程
1. 左侧筛选栏（桌面端）/ 顶部下拉筛选（移动端）：
   - 平台：全部 / iOS / Android
   - 分类：同首页分类（7 个）
   - 排序：综合热度 / 评分最高 / 最新上线 / 字母序
2. 右侧列表区：网格展示游戏卡片，每屏 24 款，支持分页或无限滚动
3. 顶部搜索框：输入关键字 → 列表实时过滤（debounce 300ms）

### 输入 / 输出 略（参考 F001）

### 验收标准（AC）
- [ ] AC1：筛选组合生效，列表结果与筛选条件一致
- [ ] AC2：搜索关键字「原神」，在任一语言下都能匹配到对应游戏
- [ ] AC3：移动端筛选交互不遮挡列表内容

## F003 · 游戏详情页
### 描述
`/{locale}/games/{slug}` 页面，展示某款游戏的完整信息和对应的攻略列表。SEO 核心落地页（搜索「XX 游戏」的用户会来到这里）。

### 用户故事
> 作为搜索「原神」来到详情页的玩家，我希望一眼看到游戏基本信息、评分、和相关攻略入口，以便继续深入阅读。

### 页面结构（从上到下）
1. **Hero 区**：横幅背景图 + 游戏图标 + 名称 + 开发商 + 发行日期 + 平台标签
2. **评分卡片区**：综合评分（百分制）+ TapTap 评分 + App Store 评分 + 玩家评价人数
3. **信息 Tab 栏**：概览 | 攻略（5） | 相关游戏
4. **概览 Tab**（默认）：游戏简介、截图轮播、分类标签、同分类推荐
5. **攻略 Tab**：攻略列表（5 篇），每篇显示封面、标题、类型标签（新手/配队/Boss...）、适用版本号、发布日期、阅读时长
6. **相关游戏 Tab**：同开发商 + 同分类的游戏推荐

### 验收标准（AC）
- [ ] AC1：SEO 元数据包含游戏名、评分、封面图，Google 搜索可出富摘要
- [ ] AC2：攻略列表点击跳转至 `/{locale}/games/{slug}/guides/{guideSlug}`
- [ ] AC3：三语切换时，游戏基本信息和攻略同时切换语言

## F004 · 攻略详情页（核心内容页）
### 描述
`/{locale}/games/{slug}/guides/{guideSlug}`，整个网站的 SEO 核心价值页（大部分搜索流量落地在攻略详情页）。

### 用户故事
> 作为卡关后搜索「XX Boss 怎么打」来到这里的玩家，我希望 30 秒内看懂打法步骤，而不是翻 10 分钟长文。

### 页面强制结构（确保结构化）
1. **面包屑导航**：首页 › 分类 › 游戏名 › 攻略标题
2. **顶部元信息条**：
   - 攻略类型 Tag（🏷️ 新手入门 / ⚔️ Boss 攻略 / 🎴 配队推荐 / 💎 抽卡建议 / ❓ 常见问题）
   - 📱 适用版本：vX.X.X（醒目颜色标签）
   - 🕒 最后更新：YYYY-MM-DD
   - ⏱️ 阅读时长：约 X 分钟
3. **TL;DR 摘要区**（折叠面板默认展开）：3-5 句话总结攻略核心结论，配一个「✅ 核心要点」清单
4. **正文区**（LLM 生成时强制结构化）：
   - 一级标题下必须是有序步骤（步骤 1、步骤 2...）
   - 关键数据（等级、属性、数值）必须用表格展示
   - 配队 / 搭配类攻略必须有角色卡片组件
5. **互动区（底部）**：
   - 👍 有用 / 👎 没用 按钮（点击后记录，不需要登录，匿名 IP 去重）
   - 分享按钮（复制链接 / 社交平台）
6. **侧边栏（桌面端）**：
   - 目录导航（锚点跳转）
   - 同游戏其他攻略推荐
   - 「你可能还喜欢」其他游戏攻略

### 验收标准（AC）
- [ ] AC1：攻略正文包含完整的 TL;DR、步骤编号、关键数值表格
- [ ] AC2：适用版本号标签存在且信息正确
- [ ] AC3：Schema.org Article 结构化数据嵌入页面，Google Rich Results Test 可识别
- [ ] AC4：「有用/没用」按钮点击后计数 +1，24 小时内同一 IP 重复点击无效
- [ ] AC5：三语切换，URL locale 变更，内容切换为对应语言

## F005 · 三语国际化（i18n）
### 描述
全站支持 zh-CN（简体中文）、zh-TW（繁体中文）、en（英文）三语，基于 Next.js App Router 的 `[locale]` 路由段实现。

### 核心规则
1. **URL 结构**：所有页面都带 locale 前缀，根路径 `/` 302 重定向到浏览器 Accept-Language 匹配的 locale（fallback=en）
2. **语言切换组件**：右上角固定语言选择器，切换时保留当前路径（不回首页）
3. **内容 fallback 策略**：
   - 游戏元信息：某语言缺失 → 回退英文 → 回退原始采集语言
   - 攻略内容：某语言缺失 → 显示「该攻略暂无此语言版本」提示，提供切换到其他语言的按钮
4. **hreflang 标签**：每个页面的 `<head>` 中必须嵌入三语的 hreflang 链接，避免搜索引擎判定为重复内容
5. **UI 文案翻译**：按钮、导航、提示文案等通过翻译字典实现，不硬编码

### 验收标准（AC）
- [ ] AC1：访问 `/`，Accept-Language=zh-CN 的用户被 302 到 `/zh-CN`
- [ ] AC2：在 `/zh-CN/games/genshin` 页面切换到英文，正确跳转到 `/en/games/genshin`，路径保持一致
- [ ] AC3：所有页面 `<head>` 包含 3 个 `<link rel="alternate" hreflang="...">` 标签

## F006 · SEO 基建
### 描述
全站 SEO 基础设置，是获取搜索流量的根本。

### 功能清单
1. **Metadata API**：每个页面用 Next.js generateMetadata() 动态生成 title、description、keywords、OG、Twitter Card
2. **Sitemap.xml**：
   - `/{locale}/sitemap.xml` 每种语言一份
   - 包含所有游戏页和攻略页的 URL，<lastmod> 取内容更新时间
   - 游戏数量多后用 sitemap index 分片
3. **Robots.txt**：允许所有爬虫，指定 sitemap 位置
4. **Schema.org 结构化数据**：
   - 首页 → `WebSite` + `ItemList`（排行榜）
   - 游戏详情页 → `VideoGame`（含 name, rating, platform, genre, publisher）
   - 攻略详情页 → `Article`（含 headline, author, datePublished, dateModified, articleSection）
5. **面包屑结构化数据**：所有内页嵌入 `BreadcrumbList` JSON-LD
6. **Canonical URL**：每个页面指定 canonical，避免重复索引

### 验收标准（AC）
- [ ] AC1：`/sitemap.xml` 返回 sitemap index，包含三语的 sitemap 链接
- [ ] AC2：`/robots.txt` 可访问，Sitemap 字段正确
- [ ] AC3：任一攻略详情页，用 Google Rich Results Test 检测，Article + BreadcrumbList 均无错误

## F008 · 内容生产流水线 - 爬虫
### 描述
离线 Python 模块，负责从多源采集游戏基础信息和原始攻略内容。V1 采集源：

| 采集源 | 采集内容 | 采集方式 | 频率 |
|--------|----------|----------|------|
| App Store RSS Feed（官方公开） | iOS Top 免费榜 / 付费榜 / 畅销榜 Top 200 | HTTPS 请求 XML 解析 | 每日 |
| TapTap 排行榜页（灰色） | 安卓热门榜 Top 200、游戏详情、评分、评测数 | Playwright 动态渲染 + HTML 解析 | 每日 |
| 4399 手游攻略区（灰色） | 手游攻略正文 | HTTP 请求 + BeautifulSoup | 每周 |
| TapTap 攻略社区帖（灰色） | 玩家社区攻略 | Playwright + HTML 解析 | 每周 |
| RAWG.io API（官方免费额度） | 游戏基础信息（多平台 slug 映射、开发商、分类、发售日） | REST API | 每日增量 |

### 爬虫输出
- 原始游戏元信息 JSON（存入 DB 的 raw_game 表，标记 source）
- 原始攻略正文 HTML + 提取的纯文本（存入 raw_guide 表，标记 source_url、采集时间、原文作者）

### 爬虫规则
- 每两次请求之间 sleep 2-5 秒（随机），设置合理 User-Agent
- URL 指纹去重（SHA-1），同一 URL 7 天内不重复采集
- 失败重试 3 次（指数退避），3 次失败写入失败队列
- 并发 ≤ 5（避免被封）

## F009 · 内容生产流水线 - LLM 处理管道
### 描述
离线 Python 模块，对爬虫产出的原始内容进行多步 LLM 处理，最终生成可发布的结构化多语言内容。

### 管道步骤（串行，每步有校验）
```
Step 1 · 信息抽取（DeepSeek-V2-Lite）
  输入：多篇同源原始攻略 HTML+文本
  输出：结构化 JSON
    { gameName, gameVersion, guideType, title, tldr,
      steps: [{stepNum, title, content, tips[]}],
      keyFacts: [{field, value, unit}],  // 关键数值（不允许LLM改）
      glossary: [{term, zhCN, zhTW, en}] // 专有名词表
    }
  校验：JSON Schema 校验通过 + 步骤数 ≥ 2

Step 2 · 简体中文攻略改写（DeepSeek V2）
  输入：Step1 的 JSON
  要求：
    - 保持事实 100% 一致（keyFacts 强制替换）
    - 增加「小编提示」人味段落（1-2 句）
    - 用 Markdown 结构化（步骤编号、表格、加粗关键信息）
    - 文本重复度 ≤ 30%（和任意源文比对）
  输出：zh-CN Markdown 正文 + 结构化 frontmatter

Step 3 · 繁体本地化（DeepSeek V2）
  输入：zh-CN Markdown
  要求：
    - 转换为繁体（台湾用语，如「充值→儲值」「程序→程式」）
    - 专有名词用 glossary 表强制替换
    - 不调整内容结构
  输出：zh-TW Markdown

Step 4 · 英文翻译润色（可选 DeepL 前置 + DeepSeek V2 润色）
  输入：zh-CN Markdown + glossary
  要求：
    - 手游俚语地道（「抽卡」→ gacha pull，「满破」→ max breakthrough）
    - 保留所有结构和表格
  输出：en Markdown

Step 5 · 自动质检（DeepSeek-V2-Lite + 规则）
  检查项：
    ✅ keyFacts 在三语中数值完全一致
    ✅ 步骤数三语一致
    ✅ 和任意源文的字符重复度 ≤ 30%
    ✅ Markdown 结构完整（无未闭合标签）
    ✅ frontmatter 完整（title、type、version、date）
  任一项不通过 → 打回 Step 2 重做（最多重试 2 次），仍失败 → 进入人工审核队列
```

### 验收标准（AC）
- [ ] AC1：给定 10 篇原始攻略，管道端到端通过率 ≥ 90%
- [ ] AC2：产出的三语攻略，keyFacts 数值一致率 100%
- [ ] AC3：和原始采集源的文本重复度平均 ≤ 25%

## 附录：通用规则
- **URL slug 规范**：游戏 slug 用英文小写字母+连字符（如 `genshin-impact`），攻略 slug 用 `{guide-type}-{关键词}`，三语共用同一 slug（不翻译）
- **时间格式**：所有日期用 ISO 8601（YYYY-MM-DD），页面展示时按 locale 本地化
- **响应式断点**：移动端 < 768px，平板 768-1024px，桌面端 > 1024px
- **缓存策略**：
  - 游戏列表/排行榜页面：ISR，revalidate=3600（1 小时重生成）
  - 游戏详情页：ISR，revalidate=7200
  - 攻略详情页：ISR，revalidate=86400（内容每天检查更新）
  - 静态资源：immutable + hash 文件名
